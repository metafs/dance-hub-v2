# p8ce — 掲載基準 / Listing Policy

**Status:** Draft
**Version:** 0.2
**Last Updated:** 2026-09-20

---

## Purpose

この文書は、どの Event を掲載するか、どの Organization を承認するか、どの条件で公開を取り下げるかの正本である。データ項目、状態遷移、認可の正本は `docs/product/requirements.md` とし、本文書はそれらを掲載判断の条件として参照する。

目的は「良い公演を選ぶこと」ではない。運営者個人の美学と、掲載可否の判断を分離することである。運営者が当事者（作家）である以上、裁量による判断はコミュニティ内の政治になる。本文書はそれを避けるために存在する。

規則は本文書に、理由は ADR に置く。

- ADR-0017 掲載審査で作品の質を判断しない
- ADR-0018 公開状態と取り下げ

公開ページ `/listing-policy`（`src/features/moderation/components/public-listing-policy-page.tsx`）は、本文書のうち利用者が拠り所にする条文を同じ番号で述べる。条文を変更するときは公開ページも同じ変更で直す。G-2・G-4 と紹介（Curation）の基準は公開しない。

## 原則

1. 審美的判断をしない。作品の質、ジャンルの正統性、団体の規模・知名度・キャリアを掲載可否の理由にしない。
2. 迷ったら掲載する。代わりに、取り下げの手順を軽くしておく。
3. 裁量ではなく条件。すべてチェックリストに落ちる形で書く。書けないものは基準にしない。
4. 不承認は条文番号で返す。「総合的に判断して」は使わない。

## 掲載（Listing）と紹介（Curation）の分離

この二つを混同しない。

| | 掲載 | 紹介 |
| --- | --- | --- |
| 判断 | 形式要件のみ。機械的 | 編集判断。主観でよい |
| 基準 | 本文書として公開する | 公開しない |
| 不採用時 | 該当条文番号を通知する | 説明義務はない |

掲載審査は作品の質を見ない。「掲載されているが今週の紹介に入らなかった」は説明可能であり、「掲載されなかった」は説明を要する。この非対称が本文書の設計理由である。

## A. 対象範囲

- **A-1** 物理 Schedule を持つ場合、開催地が対象地域内であること。
- **A-2** 身体表現・舞台芸術に関する Event であること。
- **A-3** 一般に公開されていること。誰でも申込・購入・入場できる状態を指す。完全招待制、関係者限定、チケットが一般に販売されないものは対象外。
- **A-4** 物理 Schedule を持つ場合、開催日時が確定していること。Schedule 0 件の `apply` Event は、応募締切が確定していればよい。
- **A-5** 物理 Schedule を持つ場合、Venue が特定できること。オンライン配信のみの Event は対象外。Schedule 0 件の `apply` Event はこの条件を適用しない。

対象地域は `docs/product/scope.md` を正本とする。本文書は地域を定義しない。

### A-2 の運用

ジャンルで除外しない。コンテンポラリー、バレエ、ストリート、舞踏、日本舞踊、民族舞踊、フィジカルシアター、パフォーマンスアート、ダンスを含む演劇は、すべて対象に含む。

- ダンスコンテスト・バトルは対象に含む（A-3 を満たす場合）。
- 屋外・野外パフォーマンスは対象に含む（A-3・A-5 を満たす場合）。
- 教室・スクールの発表会は除外しない。専用の区分は設けず、既存の Event Type で掲載する（下記）。
- 定期的なレギュラーレッスンは対象外。Event モデルが前提とする単発性を満たさないため。

### 発表会の扱い

発表会・成果発表の性格を持つ Event も、ほかの Event と同じ Event Type（`performance` など）で掲載する。発表会のための Event Type は設けず、一覧の既定表示からも外さない（2026-09-24、roadmap DEC-R4）。ADR-0008 の Event Type は変更しない。

## B. 形式要件

- **B-1** Event 名。
- **B-2** 物理 Schedule を持つ場合は開催日時。複数回公演はすべての回。Schedule 0 件の `apply` Event は応募締切。
- **B-3** 物理 Schedule を持つ場合は Venue 名と、特定可能な所在地。
- **B-4** 主催 Organization 名。
- **B-5** 有効な問い合わせ手段（公式サイト、SNS、メールアドレスのいずれか）。
- **B-6** 1 件以上の Ticket Offer、1 件以上の有効な外部 Ticket / 申込 Link、または申込不要の明示。
- **B-7** 物理 Schedule を持つ Event は、`Asia/Tokyo` の暦日で最初の開催日の 7 日前以前に申請されていること。Schedule 0 件の `apply` Event はこの条件を適用しない。

公開データ項目の正本は `docs/product/requirements.md` である。B はその項目を審査時のチェックリストとして表現し、掲載可否の判断には本文書を用いる。一方だけを変更せず、要件変更時は両文書を同じ変更で整合させる。

### 必須としない項目

出演 Artist、振付、演出、main image は必須としない。代理入力による掲載在庫の確保を妨げるため。

main image を登録する場合は、ADR-0016 に従って認可済みの upload・配信経路を使い、alt text を必須とする。main image がない Event Card と詳細表示も、画像ありと同等に成立する必要がある。

## C. 権利要件

- **C-1** Organizer が申請する場合、申請者がその情報を掲載する権限を持つこと（主催者本人、または許諾を得た者）。運営による代理入力には C-5〜C-8 を適用する。
- **C-2** 投稿する画像について、利用許諾を得ていること。
- **C-3** 画像に写る人物の掲載許諾を得ていること。
- **C-4** 他者の氏名を、本人の了承なく出演者として掲載していないこと。

### 運営による代理入力の要件

運営が主催者に代わって Event を入力する場合、以下をすべて満たす。

- **C-5** 転記元が一般に公開された情報であること。
- **C-6** 公開後すみやかに主催者へ通知し、修正・取り下げの窓口を示すこと。
- **C-7** 主催者からの申し出に対し、修正または `withdrawn` への変更を即時に行うこと。
- **C-8** 画像は転記しない。代理入力された Event は画像なしで公開する。

## D. 除外要件

- **D-1** 法令に違反するもの。
- **D-2** 特定の属性に対する差別・憎悪の扇動を目的とするもの。
- **D-3** 実体のないオーディション・スカウト等、参加者から不当に金銭を得る目的のもの。
- **D-4** 宗教勧誘、投資・連鎖販売の勧誘を主目的とするもの。
- **D-5** 性的サービスを主目的とするもの。
- **D-6** 虚偽の情報を含むもの。

この一覧は増やさない。「品位」「品質」「ふさわしくない」等、運用できない語を加えない。

チケットノルマ、出演料の有無、参加費徴収型の公演は、掲載基準に含めない。業界慣行への価値判断であり、条文化できないため。将来の扱いは ADR-0017 の Revisit when を参照。

## E. Organization 承認基準

ADR-0006 の Organization application 審査に適用する。

- **E-1** 団体または個人が実在し、責任者が特定できること。
- **E-2** 有効な連絡先があること。
- **E-3** 活動の実態を確認できる情報があること。公式サイト、SNS アカウント、過去公演のいずれか一つで満たす。
- **E-4** 過去に本基準への重大な違反がないこと。

実績要件は課さない。初めての公演を行う個人・団体を承認対象から外さない。

## F. 公開状態と取り下げ

Event は三つの状態を取る。決定の理由は ADR-0018 を参照。

| 状態 | 発動条件 | 一覧・検索 | 直 URL | 内部保持 |
| --- | --- | --- | --- | --- |
| `published` | 承認済み | 表示 | 表示 | あり |
| `cancelled` | 中止・延期の申告 | 中止として表示 | 表示 | あり |
| `withdrawn` | 下記 F-1〜F-5 | 非表示 | 非表示 | あり |

- **F-1** 主催者から掲載取り下げの求めがあったとき。理由を問わない。
- **F-2** 権利者からの申し立てがあり、正当と判断されたとき。
- **F-3** 情報が虚偽であったと判明したとき。
- **F-4** 安全またはプライバシー上の理由があるとき。
- **F-5** 本基準の D に該当することが公開後に判明したとき。

### 中止と取り下げの区別

中止・延期は `cancelled` として残す。チケット購入者が中止の事実を確認できる必要があるため。主催者が中止情報そのものの掲載を望まない場合は、F-1 に基づく取り下げとして扱う。

### 出演者本人からの要請

出演者本人から自身の氏名または画像の削除要請があった場合、Event 全体を `withdrawn` にせず、当該箇所のみを削除する。Event の存在自体は `published` のまま維持する。

### 操作

取り下げと復帰は Platform Admin が `/admin/withdrawals` で行う。いずれも理由が必須で、
`event_revision_audit_log` に記録される。手順は `docs/ops/runbooks/moderation.md`。

### `withdrawn` の意味

`withdrawn` は外部から見て削除と同等である。一覧・検索・直 URL のいずれからも到達できない。内部的にはレコードを保持し、ADR-0007 の承認履歴と公開 Revision、および統計の集計母数を失わない。主催者への通知および利用規約上の表現は「削除」とする。

## G. 運用ルール

- **G-1** 審査は原則 3 営業日以内に結果を通知する。超える場合は理由を通知する。
- **G-2** 審査処理量の上限は週 20 件とする。これを超える広報活動を行わない。上限は実際の申請数と審査所要時間を確認して見直す。運営による代理入力（C-5〜C-8）はこの上限に含めない（2026-09-24、roadmap DEC-R6）。
- **G-3** 不承認の通知には、該当する条文番号を記載する。
- **G-4** 条文に当てはまらない例外判断を行った場合、判断と理由を記録する。記録が三件を超えた時点で、本文書の改訂を検討する。
- **G-5** 運営関係者が出演・主催する Event も、同一の申請フローを通る。承認は運営者本人以外が行うことが望ましいが、体制上不可能な場合は、その Event のページに運営関係者が関与する旨を明示する。
- **G-6** 代理入力を行った Event には、代理入力である旨と主催者向けの修正窓口を表示する。

## 明文化しないもの

以下を基準として書かない。運用できず、恣意的な排除の入口になるため。

- 作品の質、芸術性
- ジャンルの正統性
- 団体の規模、知名度、活動年数
- 「シーンへの貢献」等の評価語

## Revisit when

- 週 20 件の審査上限が恒常的に不足したとき（G-2）
- 例外判断の記録が三件を超えたとき（G-4）
- `docs/product/scope.md` の対象地域が変わったとき（A-1）
