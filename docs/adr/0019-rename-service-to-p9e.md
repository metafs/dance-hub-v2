# ADR-0019: サービス名を p9e に変更する

**Status:** Accepted
**Accepted:** 2026-09-19
**Amended:** 2026-09-20（タグラインを決定し、読みの代替案を記録）

## Context

サービス名を DANCE HUB から変更する。理由は三つある。

**既存サービスとの衝突。** DANCE HUB という名称は既に複数の主体が使用しており、検索での分離ができない。ブランド名での指名検索が成立しない。

**掲載基準との矛盾。** `docs/product/listing-policy.md` の A-2 で、ジャンルによる除外を行わないことを決定した（ADR-0017）。コンテンポラリー、バレエ、ストリート、舞踏、日本舞踊、コンテスト、屋外パフォーマンスをすべて対象に含む。名称に dance を含むことは、この決定と矛盾する。パフォーマンスアート、フィジカルシアター、実験的な作品の主催者が、自分たちは対象外だと読む可能性が高い。

**機能語であること。** HUB は機能の説明である。名称に機能を説明させると、説明文が担うべき役割を名称が肩代わりし、かつ同種のサービスと区別がつかなくなる。

改名は Event の恒久 URL 設計（M5 Public discovery）より前に行う必要がある。公開 URL が確定した後では、改名のコストが跳ね上がる。

## Decision

サービス名を `p9e` とする。

- **表記:** `p9e`。小文字を正とする。
- **読み:** ピーナイン。
- **由来:** performance の numeronym。先頭 `p`、中間9文字、末尾 `e`。`k8s`（Kubernetes）、`i18n`（internationalization）、`a11y`（accessibility）と同じ機構。
- **タグライン:** どの上演にも、ピークがある。
- **repository:** `metafs/p9e`。
- **ドメイン第一候補:** `p9e.dance`。

### 表記の規則

- `P9` 単体は用いない。銃器、天文（Planet Nine）等で広く使用されており、識別性がない。
- 末尾の `e` は表記にのみ存在する。読みには含めない。
- 識別子として大文字が必要な箇所のみ `P9e` を用い、`P9E` は環境変数・定数に限定する。
- 名称に機能を説明させない。説明は名称直下の一行が担う。

### 一行説明とタグライン

名称に機能を説明させないため、名称の直下に二つの要素を置く。役割が異なるので混ぜない。

- **一行説明:** 関東・関西のダンスとパフォーマンスを探す。
- **タグライン:** どの上演にも、ピークがある。

一行説明が主である。誰も知らないサービスにとって、まず必要なのは「これは何か」であり、タグラインはそれが分かった後でしか機能しない。したがって既定の並びは次のとおり。

```
p9e ／ ピーナイン
関東・関西のダンスとパフォーマンスを探す
```

タグラインは about、公開ページの冒頭、印刷物など、読み手が既に文脈を持つ場所で用いる。一行説明の代わりに置かない。

### タグラインが担うもの

`p9e` の綴りは performance の numeronym だが、`performance` と `peak` の組み合わせは英語の定型句 peak performance を裏に持つ。この層を読みに背負わせるとサービス名が普通名詞になるため（後述「読み：ピーク」）、タグラインが担う。

上演は、稽古・制作・告知のすべてが一点に集まって現れ、そして消える。ADR-0018 で記録の永続性を手放した以上、本サービスの重心は「これから起きる一点」にある。タグラインはその重心を言う。

**「ピーク」は作品の優劣を指さない。** ADR-0017 は掲載審査で作品の質を判断しないと定めている。タグラインが指す peak は上演という出来事の時間構造であって、上演どうしの序列ではない。「どの上演にも」という限定はこの区別のために必要であり、省略できない。「ピークを集めました」のような、選別を含意する言い換えを公開文面で用いない。

### なぜ performance なのか

掲載対象の上位語として正確だからである。dance は対象を実際より狭く見せる。performance は `docs/product/listing-policy.md` A-2 が定義する範囲と過不足なく一致する。

### 実施

本 ADR は名称の決定のみを行う。置換の範囲と手順は `docs/plans/rename-plan.md` に定義し、実施はその計画に従う別の変更で行う。

## Alternatives considered

### DANCE HUB の継続

改名コストがゼロで、既存ドキュメントとの整合も保たれる。

採用しない。既存サービスとの衝突と、listing-policy A-2 との矛盾が解消されない。

### 意味を持つ一般語（corpus / haze / avenir / locus）

`corpus` はラテン語の身体と言語学の集積体が同一語であり、`haze` は舞台で光を可視化するための霧を指す。いずれも二重の意味を持つ。

採用しない。`locus` は映像制作会社と、舞台芸術の側でも同名のプロジェクトが存在し、複数の主体に埋まっている。`corpus`、`haze` も一般語であり検索での分離が困難。`avenir` は書体名であり、サービス名として用いる場合の商標リスクが残る。

### loc8（rebus 置換）

`locate` の置換表記。日時と Venue で上演を特定するという ADR-0010 の domain model と一致する。

採用しない。既に広く使用されている。

### 4cast（rebus 置換）

`forecast`。これから起きる上演を告げるという機能と一致し、口頭で発話できる。

採用しない。`4X` の形は for X と読まれる。4 を使う限りこの読みは消せず、思想と合致しない。

### c10y（numeronym）

contemporary / choreography / corporeality の三語が、いずれも同じ略号に潰れる。

サービス名としては採用しない。口頭で発話できない。年鑑・特集のシリーズ名として、書き言葉専用の符牒に用いる余地は残す。

### 読み：ピーク

peak にかけ、上演という出来事の一点性を指す。2モーラで発話しやすく、サービスの重心と一致する。

採用しない。綴りが復元できない。「ピーク」と聞いた者が「ピーク ダンス」で検索しても到達できず、口コミから検索への導線が切れる。ピークは「混雑のピーク」のような普通名詞であり、修飾語を足しても埋もれる。ダンスの流通経路は口コミであるため、これは発見のためのサービスにとって機能上の欠陥になる。加えて event / entertainment 領域に同音の事業者が複数あり（ピーク・ワン、ピークエンタテインメント）、口頭での識別性が低い。peak の含意はタグラインが担うため、読みに背負わせる必要がない。

### 読み：ピーキー

記憶に残りやすく、実験的な作品を扱う場としての性格を出せる。

採用しない。ピーキーは「パワーバンドが狭く扱いづらい」の意から転じて、尖った・気まぐれなものを指す。掲載基準 A-2 でジャンルによる除外を行わないと決めた以上、名称が含意で対象を狭く見せることは、DANCE HUB を捨てた理由と同じ構造の矛盾になる。教室の発表会やバレエの主催者が自分の場所だと思わない。また、掲載インフラとして不安定さを含意することは、主催者に掲載を委ねてもらう上で逆向きである。

## Consequences

- 読みを明示しない限り伝わらない。`README.md`、公開ページ、SNS プロフィールに「ピーナイン」を併記する。
- **「ピーナイン」は単独では識別力を持たない。** P9 という型番の製品（スマートフォン、タイヤ、自転車、加熱式たばこ等）の読みとして広く使われている。ただしいずれも製品であり、「ピーナイン ダンス」「ピーナイン 公演」のように修飾語と組み合わせたクエリは競合しない。口頭で名を聞いた者が検索で到達できることを、読みの要件とする。
- **タグラインは名称と一体の構成要素である。** 装飾ではないため、一行説明とあわせて公開面の設計に含める。
- 初見で何のサービスか分からない。名称直下の一行説明が必須となる。この一行は省略可能な装飾ではなく、名称と一体の構成要素として扱う。
- ブランド指名検索の流入は当初ゼロ。一般語検索が唯一の流入経路になるため、M5 Public discovery における SEO の優先度が相対的に上がる。
- `github.com/p9e` は第三者が取得済み。organization 配下の `metafs/p9e` を用いるため実害はないが、ユーザー名空間は取得できない。
- `p9e.page` / `p9e.org` は使用中。`.dance` を第一候補とする。
- SNS ハンドルは3文字では確保できない可能性が高い。複合形を想定する。
- 置換は 51 ファイル・79 箇所に及ぶ。範囲と判断が必要な箇所は `docs/plans/rename-plan.md` を参照。

## Revisit when

- `p9e.dance` が取得できなかったとき。ドメインが決まらない場合は名称ごと再検討する。
- 商標登録を検討するとき。
- 英語圏への展開を行うとき。読みの問題が英語話者に対して再燃する。
- ピーナインという読みが定着せず、現場で別の読みが自然発生したとき。その場合は自然発生した読みを正とする。
- タグラインが作品の選別を意味すると受け取られる事例が生じたとき。
